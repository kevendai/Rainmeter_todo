### 0.2 复核推翻的 3 个前提（重要，必须纠正）

1. **评分量程是两个，不是一个。** 计划与 rev2 意见都假设"0-50 分制"，代码事实是：
   - 标题阶段 **0-10**：`DefaultTitlePrompt` = "Assign an integer score from **0 to 10**"（`backend/TodoPaperService.cs:26`），`ScoreStage(...,"title",...,0,10,...)`（`:727`），`TitleThreshold` 被 `Clamp(...,0,10)`（`:175`、`:210`）。
   - 摘要阶段 **0-50**："Assign an integer score from **0 to 50**"（`:46`），`ScoreStage(...,"abstract",...,0,50,...)`（`:733`），示例 `{"scores":{"1":42,"2":26}}`（`:56`）。
   - ⇒ 计划 §3 的示例 `{"title":43,"abstract":46}` **本身就是量程混用**：43 作为 title 分在现有体系里不可能出现。`scores.title` 若照 0-50 放行，恰好会漏掉这种 provider 量程错误。**故 §6.2 采用分段校验**（title 0-10 / abstract 0-50）。
2. **`abstract_threshold` 这个字段不存在。** 设置 schema 只有 `title_threshold`（`plugins/official/arxiv/settings.schema.json:12`），`PaperSettings` 也只有 `TitleThreshold`（`TodoPaperService.cs:75`）。摘要阶段的收尾是"排序取 Top-N"（`ImportPapers`：`OrderByDescending(abstract)` → `ThenByDescending(title)` → `Take(ImportCount)`，`:1145-1148`），没有摘要阈值。⇒ 从 `profile_hash` 输入表里删除该键。
3. **"手动同步与 startup 可能重叠"是错的，撤回。** 两条路径都经过 `InvokeLocked(..., exclusive:true)`（`backend/PluginHostApp.cs:37`、`:72`、`:96-103`），互斥量名 `Global\RainmeterPluginSync_<sanitized-plugin-id>`，同一插件不可能并发同步。**但**由此暴露两个真问题，已分别写进 §4.6 与 §0.3。

### 0.3 复核新发现的 3 个既有缺陷（本次一并修）

| 缺陷 | 代码事实 | 影响 | 处置 |
| --- | --- | --- | --- |
| **取消不传播到 Provider** | `CancelPlugin`（`PluginHostApp.cs:115-119`）只依据 job JSON 里的 `pid`/`entry` 杀**插件进程**，完全不知道 Provider 子进程 | 取消 arxiv 后 DeepSeek 请求进程会变孤儿 | §4.6（Phase 1 必须做） |
| **取消窗口很窄** | `WriteJob` 在 `state != "running"` 时就把 `pid`/`entry` 从 job JSON 删掉（`PluginHostApp.cs:107`） | job 一旦 completed/failed/cancelled，`Cancel` 永远返回 1，无补救 | §4.6 改为按 `job_id` 校验 |
| **重复点击会把 job 打成 failed** | 第二个同步请求在 `InvokeLocked` 抛"该插件已有同步任务正在运行"，冒泡到 `SyncAll` 的 catch → `WriteJobState(id,"failed",...)`（`PluginHostApp.cs:75`）；单插件路径同理（`:56`） | 用户手快双击 ⇒ 正在跑的任务被误标失败 | §4.7 新增 `busy` 判定，不得覆盖 running 状态 |
| **`attention` 实际上无人显示** | 读侧唯一处理点在 `PluginRuntimeStatus`（`PluginManagerForms.cs:373-388`），开头就 `if(!manifest.Capabilities.Contains("value_provider"))return "";` —— 对 arxiv（`todo_source`）直接短路；且文案前缀是"失败：" | §5 的 `attention` 对 arxiv **完全不生效** | §5.5 必须落皮肤侧 |

## 1. 接口版本与兼容（rev2 重写）

### 1.1 两个版本概念必须分开

```text
api_version      = PluginHost JSON Lines 基础通信协议版本   → 本次保持 1
ai_provider@1    = 某项服务接口的协议版本                    → 本次新增
```

| 判据 | 现状 | 本次 |
| --- | --- | --- |
| `api_version` 校验 | `PluginRuntime.cs:65` 写死 `ApiVersion != 1` → 拒绝 | **不动**，仍为 1 |
| 新机制（`provides`/`uses`/`context.services`/`ServiceCall`/`status`） | 无 | 全部为**加法式扩展**：旧插件（`api_version:1`、无新字段）行为完全不变 |

理由（维护者原话复述）：等 JSON Lines 基础协议本身真有 breaking change 再升 `api_version=2`；否则会平白增加 Calendar-to-Todo、SSDP、第三方 v1 插件的兼容复杂度。

### 1.2 `status` 字段也是加法式的

插件结果信封与 Broker 响应都新增顶层 `status`（缺省 `"ok"`）。因为缺省即现状语义，**旧宿主读新插件、新宿主读旧插件都不会崩**，所以不需要动 `api_version`。

### 1.3 `capabilities` 与 `provides` 不是一回事（不许合并）

| | `capabilities` | `provides` |
| --- | --- | --- |
| 语义 | 宿主**可以主动执行**的插件入口类型 | 插件**能提供给别的插件**的服务 |
| 谁用 | 宿主（`PluginHostApp.cs:71`、`:82`、`PluginManagerForms.cs:300`） | Broker 绑定解析 |
| 取值 | 白名单 `todo_source` / `todo_transform` / `value_provider`（`PluginRuntime.cs:68`、`PluginPackageInstaller.cs:29`） | `^[a-z0-9_]+@[0-9]+$` |

**明确不做**：把 `ai_provider` / `translation_provider` / `paper_snapshot_provider` 塞进 `capabilities` 白名单 —— 那会让两套系统重复表达同一件事。

校验放宽（唯一改动）：

```csharp
// PluginRuntime.cs:69 现状
if (Capabilities.Count==0 || Capabilities.Any(x=>!allowed.Contains(x))) throw ...
// rev2
if (Capabilities.Count==0 && Provides.Count==0) throw new InvalidDataException("插件既无 capability 也不提供任何服务");
if (Capabilities.Any(x=>!allowed.Contains(x))) throw new InvalidDataException("插件 capability 无效");
```

即：`capabilities` **可以为空**（纯 Provider 插件），但必须**要么能被宿主调用，要么能提供服务**。`PluginPackageInstaller.cs:29,56-62` 同步同一规则。既有三个白名单值**一个都不改**。

## 2. manifest 增量（`plugin.json`）

Consumer（arxiv 2.0.0）：

```json
{
  "api_version": 1,
  "min_host_version": "2.1.0",
  "capabilities": ["todo_source"],
  "uses": [
    { "service": "paper_snapshot_provider@1", "optional": true, "binding_key": "paper_snapshot_provider" },
    { "service": "ai_provider@1",             "optional": true, "binding_key": "ai_provider" },
    { "service": "translation_provider@1",    "optional": true, "binding_key": "translation_provider" }
  ]
}
```

Provider（如 ai-deepseek 1.0.0）：

```json
{
  "api_version": 1,
  "capabilities": [],
  "provides": ["ai_provider@1"],
  "billing": "may_charge"
}
```

规则：

1. `provides[]` 与 `uses[].service` 匹配 `^[a-z0-9_]+@[0-9]+$`；`binding_key` 缺省 = service 去版本，匹配 `^[a-z0-9_]+$`。
2. `optional` 默认 `true`；`false` 表示硬依赖 —— 安装/启用时找不到候选要**警告**（仍允许装），运行时返回 `no_provider`。
3. **声明 `provides`/`uses` 不要求 `api_version >= 2`。**
4. 宿主不认识某个 service 名**不是错误**（宿主在此处刻意保持"不懂业务"）。
5. 同步更新 `schemas/plugin-manifest-v1.schema.json`。
6. `permissions`/`billing` 均**只声明不强制**（见 §6.4）。

## 3. 绑定存储 `plugin-bindings.json`

位置：`%LOCALAPPDATA%\RainmeterDesktopWidgets\plugin-bindings.json`（与 `PluginValues.json`、`migration-v2.json` 同级；在 `PluginPaths` 加常量）。

```json
{
  "version": 1,
  "bindings": {
    "io.github.kevendai.arxiv": {
      "paper_snapshot_provider@1": "io.github.kevendai.paper-snapshot-sync",
      "ai_provider@1": "io.github.kevendai.ai-deepseek",
      "translation_provider@1": null
    }
  }
}
```

- **写者**：宿主独占（设置页选择、迁移、唯一候选自动绑定）。**不暴露给插件**（插件只能看到解析结果，看不到表，也不能改）。
- **解析算法（固定顺序）**：
  1. 有绑定 → 校验：已安装 && `enabled` && `provides` 含该 `service@version`。通过则用它。
  2. 有绑定但校验失败（卸载/禁用/版本不符）→ **视为无 provider，不回落、不自动改绑**。
  3. 无绑定 → 统计候选（已安装 && `enabled` && `provides` 该 service）：恰好 1 个 → 自动绑定并记日志；≥2 个 → **不自动选**，视为未绑定；0 个 → 无 provider。
  4. **禁止**按 `priority`、安装顺序、id 字典序、市场排序挑选。`priority` 只属于 `address_provider`（`Common.cs:493-513`），不参与 service 解析。
- 呈现给 consumer（两处，内容一致）：
  - `context.services`（`PluginRuntime.Invoke` 请求内，`PluginRuntime.cs:129-132`）：
    ```json
    { "paper_snapshot_provider": {"provider_id":"io.github.kevendai.paper-snapshot-sync","provider_name":"Paper Snapshot Sync","available":true},
      "ai_provider": {"provider_id":null,"provider_name":"","available":false,"reason":"not_installed"} }
    ```
  - 环境变量 `RW_SERVICE_<BINDING_KEY 大写>_PROVIDER` / `_NAME`，让插件**不调 Broker 就能判断有没有**。
- `reason` 枚举：`not_installed` | `disabled` | `ambiguous` | `version_mismatch`。

## 4. Broker 调用协议

### 4.1 入口

```text
PluginHost.exe -Mode ServiceCall -RequestFile "<path>" [-OutputFile "<path>"]
```

- 由 **consumer 插件**发起，这是插件唯一被允许的跨插件动作。
- 输出：`-OutputFile` 或 stdout 单行 JSON（与现有 `PluginAction` 的 `-OutputFile` 习惯一致，`PluginHostApp.cs:30-31`）。
- stderr 落 `PluginLogs\<consumer-id>.log`。

### 4.2 为什么用请求文件

中文 prompt 与长 JSON 在本仓库历史上多次被 PS 5.1 GBK / `Join-Path` / `.ps1` 源码编码坑到。文件统一 **UTF-8 无 BOM**，一次写清。

### 4.3 请求与响应

请求文件（**顶层键白名单，多一个都拒**）：

```json
{
  "protocol": 1,
  "request_id": "8b7c…",
  "service": "ai_provider@1",
  "action": "structured_complete",
  "input": { },
  "timeout_seconds": 600
}
```

成功：

```json
{ "protocol": 1, "request_id": "8b7c…", "ok": true, "status": "ok", "output": { }, "error": "", "error_kind": "", "warnings": [] }
```

**attention（正式结果，不是错误）**：

```json
{ "protocol": 1, "request_id": "8b7c…", "ok": true, "status": "attention",
  "output": { "attention": { "type": "paid_service_confirmation", "service": "ai_provider@1",
                             "message": "远端论文同步失败，是否使用 DeepSeek AI 重新评分？" } },
  "error": "", "error_kind": "" }
```

失败：

```json
{ "protocol": 1, "request_id": "8b7c…", "ok": false, "status": "error", "output": null,
  "error": "可读中文原因", "error_kind": "no_provider", "fatal": false }
```

`error_kind` 枚举（**consumer 必须按 kind 分支，不许按 error 文本判断**）：

| error_kind | 含义 | consumer 行为 |
| --- | --- | --- |
| `no_provider` | 绑定不存在/失效/待选 | 走"无该 Provider"分支（**不是失败**） |
| `input_invalid` | input 非法 | 记错误，本轮失败，不重试 |
| `provider_denied` | 需要用户同意但未获得 | 本轮结束，**0 次 API 调用** |
| `provider_error` | provider 明确报错 | 看 `fatal`：true 立即中止整轮；false 记 warning |
| `provider_timeout` | 超过 `timeout_seconds` | 重试一次后放弃 |
| `provider_crashed` | provider 进程异常退出/输出违规 | 记错误，不重试 |
| `protocol_error` | 响应结构不符 | 记错误，不重试 |
| `broker_depth_exceeded` | 二级转发被拒（§4.4） | 记错误，不重试 |

`timeout_seconds` 由 consumer 建议、**宿主强制**上限（默认 600，最大 1800）；超时由宿主杀 provider 进程。

审计：每次调用追加一行到 `PluginLogs\service-call.log`：`时间 | consumer | provider | service | action | 耗时ms | ok/status/error_kind | billing`。**不记录 input 正文**（可能含论文摘要），只记字段名与字节数。

### 4.4 Caller identity：只认环境变量，请求 JSON 里没有 provider（rev2 硬约束）

**宿主启动 consumer 时注入**（在 `ApplyPluginEnvironment`/`BuildChildEnvironment`，`PluginRuntime.cs:172-196` 一处扩展）：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `RW_PLUGIN_ID` | consumer 插件 id | Broker 判定"谁在调" |
| `RW_PLUGIN_JOB_ID` | 宿主为该次 job 生成的 uuid，同时写进 `PluginJobs\<id>.json` 的 `job_id` | 取消传播（§4.6）、depth 判定 |
| `RW_PLUGIN_HOST_EXE` | Broker 入口（`PluginHost.exe` 全路径） | 让插件有稳定入口 |
| `RW_PLUGIN_DATA_DIR` / `RW_WINDOW_SCALE` | 既有 | 不变 |

**请求文件里禁止出现 `provider_id` / `consumer` / `binding_key`**：

- 出现任何白名单外的顶层键 → `protocol_error`。
- 插件**只报 service 名**，provider 由宿主按绑定解析 ⇒ 插件无从"偷偷换 provider"，§8 的三条禁令天然成立。

**Broker depth = 1（v2.1 写死）**：允许 `arxiv → ai_provider`，**拒绝** `arxiv → Provider A → Provider B`。

实现方式（机制而非约定，双保险）：

1. **机制**：Broker 启动 provider 时**不注入 `RW_PLUGIN_HOST_EXE`**（并在 `ApplyPluginEnvironment` 里把该键从子环境块中显式剔除，否则会随环境块继承下去）。provider 找不到 Broker 入口，物理上无法转发。
2. **双保险**：宿主在 `ServiceCall` 入口检查自身环境块 —— `RW_SERVICE_CALL_DEPTH` 已存在 → 直接返回 `broker_depth_exceeded`，不发进程。

### 4.5 插件执行隔离（沿用 2.0.4 契约）

`PluginRuntime.Invoke` 的既有语义不变：父宿主 fork 插件、写请求 JSON 到 stdin、同步读 stdout 到收尾（`PluginRuntime.cs:134-161`）。Broker 调用 provider 复用同一函数，所以 provider 也天然享有 request_id 校验、超时、行数/字节上限、退出码校验。

### 4.6 取消传播（rev2 新增，Phase 1 必做）

现状（§0.3）：`CancelPlugin` 只杀插件进程，Provider 子进程会留成孤儿；且 job 非 running 后 `pid`/`entry` 被删除，再也没法取消。

规定：

1. job 启动时写 `job_id` + `pid` + `entry`（现有 `pid`/`entry` 保留）。
2. Broker 启动 provider 后，把 `{job_id, broker_pid, provider_pid, started_at}` 追加到 job JSON 的 `children[]`（用同一把 `Global\RainmeterPluginJob_<id>` 锁保护，`PluginHostApp.cs:107` 已有该锁）。
3. `CancelPlugin` 顺序：**先 provider → 再 broker → 最后 consumer**；每一步都用 `MainModule.FileName` 比对登记的路径（沿用现有"进程身份已变化，拒绝终止"校验），任一 PID 已被复用则跳过而不误杀。
4. **子进程自保**：Broker 与 provider 各自监视父进程，父进程消失即自行退出（沿用更新器已验证的 `WaitForProcess(parentPid)` 做法，见 `UpdaterHostApp.cs`）。这样即使 3 的杀进程在某一步失败，也不会留下后台请求。
5. 取消不再依赖 `pid`/`entry` 是否还在 job 里 —— 改按 `job_id` + `children[]` 判定（修掉 §0.3 的第二个缺陷）。

结果：**取消 arxiv ⇒ DeepSeek 请求进程不会留在后台。**

### 4.7 `busy` 语义（rev2 新增）

单飞锁拒绝第二个同步时（`PluginHostApp.cs:101` 抛"该插件已有同步任务正在运行"），**不得**把 job 写成 `failed`。新增判定：捕获到该异常 → 保留 `state=running`、`message="已有同步任务正在运行"`，退出码 0。

## 5. 确认动作（一律阻塞，仅在用户明确同意时运行）

### 5.1 为什么付费确认不能放进插件进程（措辞更正）

严格讲，`PluginHost 等 arxiv` + `arxiv 等 MessageBox` **不构成 2.0.2→2.0.3 那种"父等子、子等父"的环形互锁** —— 用户点了按钮，arxiv 还是会继续。rev1 把这点说重了，此处更正。

**但结论完全不变：任何付费确认都不放进插件进程**，理由是：

- 后台同步触发时没有前台窗口，模态框可能根本没人看得到，却把 job 挂在那里；
- 窗口焦点/置顶无法保证（Rainmeter 是桌面层，TodoHost 是隐藏窗口进程）；
- 超时语义混乱：等用户十分钟算不算超时？超时该杀进程还是丢结果？
- Rainmeter 启动阶段（`Startup` 触发）弹模态会拖住整个启动链；
- 无人值守执行（定时、`SyncAll`）下，"等待"与"失败"无法区分。

⇒ 采用维护者给的流程（§5.2）：**不是暂停原进程，而是让它带着 `attention` 正常退出，由用户点按钮重新启动一次**。代码事实也支持这条：`attention` 目前只在 UI 读侧出现、**没有任何生产者**；arxiv 里那个 confirm 是恒返回固定值的桩（`ArxivPluginApp.cs:223-225`）。

### 5.4 job 状态机（rev2）

```text

                   ├──► failed
```

## 6. PaperBundle v1

### 6.1 结构

```json
{
  "schema_version": 1,
  "profile_hash_version": 1,
  "source": "arxiv",
  "date": "2026-09-16",
  "profile": {
    "categories": ["cs.CV"],
    "exclude_categories": [],
    "profile_hash": "…64 hex…"
  },
  "generator": {
    "type": "ai",
    "provider_id": "io.github.kevendai.ai-deepseek",
    "model": "deepseek-chat",
    "producer_version": "io.github.kevendai.arxiv 2.0.0",
    "generated_at": "2026-09-16T08:10:00+08:00"
  },
  "papers": [
    {
      "id": "2609.01234",
      "title": "Original English Title",
      "translated_title": null,
      "abstract": "…",
      "authors": ["…"],
      "categories": ["cs.CV"],
      "published_at": "2026-09-16T00:30:00+08:00",
      "url": "https://arxiv.org/abs/2609.01234",
      "pdf_url": "https://arxiv.org/pdf/2609.01234",
      "scores": { "title": 8, "abstract": 46 }
    }
  ]
}
```

注意示例已修正：`title: 8`（0-10 制）、`abstract: 46`（0-50 制）。

### 6.2 字段与校验（远端 JSON 视为**不可信输入**）

| 字段 | 必填 | 校验 |
| --- | --- | --- |
| `schema_version` | ✅ | 必须 == 1；其他值 → `incompatible`（**不是 error**，不得重试） |
| `profile_hash_version` | ✅ | 必须 == 1 |
| `source` | ✅ | 必须 == `arxiv` |
| `date` | ✅ | `YYYY-MM-DD`，按 Asia/Shanghai 解释 |
| `profile.categories` | ✅ | 字符串数组；元素匹配 `^[A-Za-z0-9._-]+$` |
| `profile.exclude_categories` | ✅ | 同上，可为空数组 |
| `profile.profile_hash` | ✅ | 64 位小写 hex，必须与本地现算值一致，否则 `incompatible` |
| `generator.type` | ✅ | `ai`（预留 `remote` / `manual`） |
| `papers[]` | ✅ | 数量上限 500（超出 → `incompatible`） |
| `papers[].id` | ✅ | 非空、**全表唯一**（重复 → `incompatible`） |
| `papers[].title` | ✅ | 非空，长度 ≤ 1000 |
| `papers[].abstract` | ➖ | 可空；长度 ≤ 20000 |
| `papers[].scores.title` | ✅ | **整数 0-10**（依据 §0.2：`TodoPaperService.cs:26,727`） |
| `papers[].scores.abstract` | ✅ | **整数 0-50**（依据 `:46,733`） |
| `papers[].url` / `pdf_url` | ✅ | 必须 https 且 host ∈ {`arxiv.org`, `www.arxiv.org`, `export.arxiv.org`} |
| `papers[].published_at` | ➖ | 可空；非空时必须可解析 |
| 整个文件 | ✅ | 字节上限 8 MB（与 `PluginPackageInstaller` 风格一致） |

**分段量程必须显式校验并给出可读原因**：`scores.title > 10` ⇒ `incompatible`，理由写"标题分超出 0-10 量程（疑似把 0-50 的摘要分写进了 title）"。这正好能抓住计划 §3 例子里那种混用量程的 provider。

判定三态（严格区分）：

- `compatible`：通过 → 可直接导入；
- `incompatible`：**结构合法但不是给我们用的**（hash 不符、schema_version 未知、source 不符、量程越界）→ 记 warning，走 AI fallback 询问，**不得导入**；
- `error`：取不到/解析失败/网络失败 → 记 `Snapshot Sync failed: …`，走 AI fallback 询问。

### 6.3 `profile_hash` 定义（rev2 定稿）

对下列**规范化 JSON**（键按字典序、数组去重后升序、字符串 trim、数字取最简形式）取 **UTF-8 字节的 SHA-256 小写 hex**：

```json
{
  "paper_bundle_schema_version": 1,
  "scoring_version": 1,
  "source": "arxiv",
  "categories": ["cs.CV"],
  "exclude_categories": [],
  "title_prompt": "…",
  "abstract_prompt": "…",
  "title_threshold": 7,
  "title_batch_size": 10,
  "abstract_batch_size": 3,
  "import_count": 5
}
```

- **纳入**：论文集合与排序语义相关的一切（上表全部）。
  - `scoring_version`：**显式递增的评分算法版本**；将来只改算法不改 prompt 时用它失效旧快照。本次 = 1。
  - `title_batch_size` / `abstract_batch_size`：**纳入**（已冻结，见 §13）。理由：批的组成会改变模型的打分（同批次内相互参照），所以"批大小变了、分数可能变"，不当它是语义无关项。
- **不纳入**：`cache_days`（只影响本地缓存有效期，不影响集合语义；注意它**不进 hash 但仍是缓存有效期**）、所有 `api_*` / `file_*` / `translate_*` 凭据与地址、UI 偏好。
- **不存在的键不许写进表**：`abstract_threshold` 在当前实现里不存在（§0.2），已删除。
- Prompt 规范化 = **CRLF → LF，然后 `Trim()`**（与现实现 `settings.TitlePrompt.Trim()` 一致，`TodoPaperService.cs:208-209`）。
- **本地缓存同样必须携带并校验 `profile_hash`**：命中前提 = 同日期 + hash 一致 + 校验通过 + 不是 partial。用户上午 `cs.CV/阈值7`、下午改成 `cs.CV+cs.AI/阈值9`，当天缓存必须立即失效。
- **字段列表写死在这里**：将来加 profile 字段，必须显式决定是否纳入 hash。

### 6.4 billing 元数据（仅展示 + 宿主策略，不是权限）

provider manifest 可声明 `"billing": "may_charge" | "local" | "free"`。只用于：设置页与确认框的费用文案、`service-call.log` 审计字段、宿主"后台绝不自作主张"的策略判断。**不要**当成能强制执行的权限 —— `permissions` 在本项目从来只声明（安装对话框已明说"不能限制系统访问"）。本批**不做** `local` 免确认的例外。

## 7. 三个官方 Provider 的契约

### 7.1 `io.github.kevendai.paper-snapshot-sync` 1.0.0（`provides:["paper_snapshot_provider@1"]`，`billing:"free"`）

- 配置页：`启用` / `自动下载`(默认开) / `Server URL` / `Account` / `Password`(`x-secret`) / `[测试连接]`。
- 声明 **`address_target: "paper_snapshot.file_server"`**（**取代** arxiv 的 `arxiv.file_server`）；被 SSDP 接管时沿用 2.0.4 的只读 + 说明交互（`x-address`）。
- actions：

| action | input | output |
| --- | --- | --- |
| `get_snapshot` | `{source, date, profile_hash}` | `{found:true, snapshot:{…}}` / `{found:false}` |
| `put_snapshot` | `{snapshot:{…}}` | `{stored:true, remote_path:"…"}` |
| `test_connection` | `{}` | `{ok:true, message:"…"}` |

- `found:false`（服务器明确回答"没有"）与 `ok:false`（请求失败）**严格区分**：HTTP 404 → `found:false`；401/403/5xx/超时/DNS → `ok:false`。
- `put_snapshot` 失败不得让本轮同步失败（consumer 记 warning 后继续导入）。

### 7.2 `io.github.kevendai.ai-deepseek` 1.0.0（`provides:["ai_provider@1"]`，`billing:"may_charge"`）

- 配置页：`API URL` / `API Key`(`x-secret`) / `Model` / `Timeout` / `Max Concurrency` / `[测试连接]`。
- actions：

| action | input | output |
| --- | --- | --- |
| `structured_complete` | `{messages:[{role,content}], response_schema:{…}, purpose:"arxiv_title_scoring"}` | `{json:{…}, usage:{prompt_tokens,completion_tokens}}` |
| `test_connection` | `{}` | `{ok:true, message:"模型可用"}` |

- **只负责模型调用**：endpoint / key / model / timeout / retry / max concurrency / 请求与返回格式 / 厂商错误解析。**不知道**什么是 arXiv、不知道 prompt 的业务含义、不知道两阶段评分规则。
- 把 2.0.4 的错误语义**搬进来**（不是重写）：401/402/403 → `fatal:true` + 可读中文（余额不足 / Key 无效 / 被拒绝）；`AggregateException` 拍平；429/5xx 内部有限重试。
- **两阶段评分（标题批量 → 阈值筛选 → 摘要 → 排序 → Top-N）留在 arxiv**，换 provider 时算法不变。

### 7.3 `io.github.kevendai.translate-tencent` 1.0.0（`provides:["translation_provider@1"]`，`billing:"may_charge"`）

- 配置页：`Secret ID`(`x-secret`) / `Secret Key`(`x-secret`) / `Source Language` / `Target Language` / `[测试连接]`。
- actions：

| action | input | output |
| --- | --- | --- |
| `translate` | `{texts:[…], source_language:"en", target_language:"zh-CN"}` | `{translations:[…]}` |
| `test_connection` | `{}` | `{ok:true, message:"…"}` |

- **必须批量**（一次一批 title，绝不每篇启一次 provider）；`translations.length` == `texts.length`，否则 `protocol_error`。
- **只在最终 Top-N 确定后翻译**；结果按 `sha256(title)` 本地缓存，重评不重复付费。

### 7.4 设置页分组与高级项（rev2 还债）

现状：`ShowPluginConfig`（`PluginManagerForms.cs:391-421`）按 `x-order` 把 `properties` **平铺**渲染，**没有 section**；`x-advanced` 在 schema 里用了 14 处（arxiv 5 处、ssdp 2 处）但**后端零实现**，`docs/PLUGIN-API.md` 却声称支持。本次一并还掉：

```json
"title_prompt": { "type":"multiline", "title":"标题评分 Prompt",
                  "x-section":"评分", "x-order":10, "x-advanced":true }
```

- `x-section`：字符串分组名；宿主按 `x-section` 分组渲染，组间加分隔标题；缺省落"基本"组。组顺序 = 组内最小 `x-order`，保证稳定。
- `x-advanced:true`：折叠进"高级设置 ▼"，默认收起。
- 枚举字段已是 ComboBox（`:407`），Provider 下拉复用它；Disabled 控件**无先例**，参考 `x-address` 的 ReadOnly 先例（`:409`）。
- 受益方是所有插件，不只是 arxiv。

### 9.2 `migration-v2.1.json`（rev2：**复制不删除**）

```json
{ "version": 1, "applied_at": "2026-09-16T…",
  "steps": { "deepseek": "ok", "tencent": "skipped", "fileserver": "ok", "papercache": "kept" } }
```

- **幂等**：step 级 marker，重复运行只补未完成的 step。
- **备份**：动手前走既有 `TodoBackupService` 快照。
- **原子**：① 写 provider 的 config/secret（**新文件**）→ ② 读回校验 → ③ 写 marker。任一步失败 → 不写 marker、记 warning、下次启动重试。
- **⚠️ 复制，不删除**：**不**从 arxiv 的 `config.json` / `secret.dat` 里删旧键。arxiv 2.0.0 只是**不再读**它们。这样：

  ```text
  2.0.4 + arxiv 1.0.2
          │  v2.1 migration（复制）
          ▼
  旧 arxiv secret ──── 原样保留 ────┐
                                    │ rollback
  同时复制一份 ▼                     ▼
  ai-deepseek / translate-tencent / paper-snapshot-sync   ←→   arxiv 1.0.2 立刻可用
  ```

  否则"一键回退 1.0.2"会得到一个**没有配置**的旧插件（§10 的回滚保护就成了一句空话）。清理旧键推迟到 arxiv **2.1.0**，且清理前必须再问维护者。
- **自动安装 ≠ 自动允许付费**：仅在"旧 arxiv 配了有效 api_key"时自动安装并启用 ai-deepseek、自动绑定；但**首次 AI 调用仍必须用户明确同意**（§5）。
- 旧 `paper-cache` / `papers.json`（无 `profile_hash`）：**保留文件但不使用**，禁止删除用户数据。

## 12. 本批明确不做

计划 §26 全部沿用，另加/修正：
