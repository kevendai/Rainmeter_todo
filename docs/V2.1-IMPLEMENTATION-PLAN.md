# 一、改造目标

当前 `io.github.kevendai.arxiv` 插件承担的职责过多，内部同时包含：

- arXiv/RSS 获取与论文解析
- 分类过滤
- DeepSeek 两阶段评分
- DeepSeek API 配置与错误处理
- 腾讯云标题翻译
- 文件服务器论文 JSON 下载与上传
- 本地论文缓存
- Paper RSS Server
- 最终 TaskDraft 生成

v2.1 的目标是在不破坏现有 Todo、PluginHost 和 Plugin API v1 基础能力的前提下，将其中与论文业务无关的能力拆成独立 Provider。

最终形成：

```text
                       Arxiv Plugin
                  （论文领域业务核心）
                           │
          ┌────────────────┼─────────────────┐
          │                │                 │
          ▼                ▼                 ▼
 Paper Snapshot       AI Provider      Translation Provider
    Provider
          │                │                 │
          ▼                ▼                 ▼
 文件服务器同步        DeepSeek           Tencent
 WebDAV / SFTP         OpenAI             DeepSeek
 ...                   Claude             OpenAI
                       Ollama             Ollama
```

核心原则：

1. `Arxiv Plugin` 必须能够独立安装和运行。
2. Paper Snapshot、AI、Translation 都是可选 Provider。
3. Provider 不直接读写 Todo 数据。
4. Provider 不直接启动其他 Provider。
5. 所有跨插件调用统一由 `PluginHost` 编排。
6. 所有可能产生付费 API 调用的 AI 评分必须经过用户明确确认。
7. 后台自动同步不得擅自触发付费 AI。
8. Translation Provider 缺失不得导致论文同步失败。
9. Paper Snapshot 优先于 AI，避免已有结果时再次消耗 API。
10. 用户拒绝 AI 评分后，本次同步直接结束，不导入未经评分的论文。

# 二、最终插件划分

## 1. Arxiv Plugin

插件 ID：

```text
io.github.kevendai.arxiv
```

能力继续保留：

```text
todo_source
```

它是整个论文推荐流程的业务编排器。

### Arxiv Plugin 保留

- arXiv RSS / API 获取
- arXiv Paper 数据解析
- 分类筛选
- 排除分类
- 两阶段评分流程的业务逻辑
- Title Prompt
- Abstract Prompt
- Title Threshold
- Abstract Threshold
- Batch Size
- Import Count
- Cache Days
- PaperBundle 生成与解析
- 本地 PaperCache
- 最终 PaperBundle → TaskDraft
- 论文 Todo policy
- Paper RSS Server
- 论文推荐状态展示

> 注：原案此处写的「Abstract Threshold」在现实现里**不存在**（只有 `title_threshold`，摘要阶段是排序取 Top-N）。见 spec §0.2。

### Arxiv Plugin 删除

- DeepSeek API URL
- DeepSeek API Key
- DeepSeek Model
- DeepSeek HTTP 请求代码
- DeepSeek 401/402/403 等厂商专用错误处理
- 腾讯翻译 SecretId / SecretKey
- 腾讯翻译 HTTP 请求
- 文件服务器 URL
- 文件服务器账号密码
- 文件服务器 JSON 上传/下载实现
- SSDP 文件服务器地址接管逻辑

这些全部移动到对应 Provider。

# 三、统一 PaperBundle v1

Provider 之间不得交换 Todo 内部 Task JSON。

新增稳定的论文中间格式：

```text
PaperBundle v1
```

示例：

```json
{
  "schema_version": 1,
  "source": "arxiv",
  "date": "2026-09-16",

  "profile": {
    "categories": ["cs.CV"],
    "exclude_categories": [],
    "profile_hash": "..."
  },

  "generator": {
    "type": "ai",
    "provider_id": "io.github.kevendai.ai-deepseek",
    "model": "deepseek-chat",
    "generated_at": "2026-09-16T08:10:00+08:00"
  },

  "papers": [
    {
      "id": "2609.01234",
      "title": "Original English Title",
      "translated_title": null,
      "abstract": "...",
      "authors": ["..."],
      "categories": ["cs.CV"],
      "published_at": "...",
      "url": "https://arxiv.org/abs/2609.01234",
      "pdf_url": "https://arxiv.org/pdf/2609.01234",

      "scores": {
        "title": 8,
        "abstract": 46
      }
    }
  ]
}
```

> 注：`scores` 示例已按真实量程修正（title 0-10、abstract 0-50）。原案写的 `title: 43` 是量程混用。

## profile_hash

必须加入 `profile_hash`，用于判断远端论文 JSON 是否与当前配置兼容。

至少应纳入：

- categories
- exclude_categories
- title_prompt
- abstract_prompt
- title_threshold
- abstract_threshold
- import_count
- 与评分结果相关的其他参数

不建议纳入：

- AI Provider API Key
- 文件服务器地址
- Translation Provider
- UI 设置

如果 Snapshot 返回的 `profile_hash` 与当前 Arxiv 配置不一致，则视为：

```text
snapshot incompatible
```

不得直接导入。

> 注：最终的 hash 输入表（含 `paper_bundle_schema_version`、`scoring_version`、prompt 规范化、批大小）以 spec §6.3 为准；`abstract_threshold` 已删除（字段不存在）。

# 四、Paper Snapshot Provider

建议正式名称：

```text
Paper Snapshot Sync
```

插件 ID：

```text
io.github.kevendai.paper-snapshot-sync
```

Capability：

```text
paper_snapshot_provider
```

> 注：冻结规格里写作 `paper_snapshot_provider@1`，走 `provides`，不占 `capabilities`。

它负责：

> 保存和获取已经生成好的 PaperBundle。

它不负责：

- arXiv 抓取
- AI 评分
- Prompt
- 翻译
- Todo 导入

## API

### get_snapshot

请求：

```json
{
  "action": "get_snapshot",
  "input": {
    "source": "arxiv",
    "date": "2026-09-16",
    "profile_hash": "..."
  }
}
```

成功：

```json
{
  "found": true,
  "snapshot": {
    "...": "PaperBundle"
  }
}
```

找不到：

```json
{
  "found": false
}
```

网络错误：

```json
{
  "ok": false,
  "error": "..."
}
```

注意：

`found=false` 与 Provider 请求失败必须严格区分。

### put_snapshot

```json
{
  "action": "put_snapshot",
  "input": {
    "snapshot": {
      "...": "PaperBundle"
    }
  }
}
```

### test_connection

用于设置页测试连接。

## 配置迁移

当前 Arxiv Plugin 内：

```text
file_enabled
file_url
file_account
file_password
```

迁移到 Paper Snapshot Sync。

旧用户升级时：

```text
旧 Arxiv 文件服务器配置
        ↓
Paper Snapshot Sync PluginData
```

如旧配置中启用了文件服务器，则：

- 自动安装官方 Paper Snapshot Sync
- 自动启用
- 自动绑定给 Arxiv
- 迁移凭据
- 不要求用户重新填写

> 注：「迁移凭据」按 spec §9.2 是**复制**，原 arxiv 的 config/secret 保留一个版本周期。

# 五、AI Provider

新增 Capability：

```text
ai_provider
```

第一批官方实现建议：

```text
io.github.kevendai.ai-deepseek
```

后续：

```text
io.github.kevendai.ai-openai
io.github.kevendai.ai-claude
io.github.kevendai.ai-ollama
```

> 注：冻结规格为 `ai_provider@1`，且本批**只做 DeepSeek**（Ollama 移出）。

## AI Provider 职责

AI Provider 只负责模型调用：

- API Endpoint
- API Key
- Model
- Timeout
- Retry
- Max Concurrency
- 请求格式
- 返回格式
- 厂商错误解析
- Token / HTTP 错误
- Connection Test

它不知道：

- 什么是 arXiv
- 什么论文值得推荐
- Title Prompt 的业务含义
- 两阶段评分规则
- Todo

## API

v1 建议至少提供：

```text
structured_complete
test_connection
```

未来可以增加：

```text
chat
complete
embeddings
```

但本次不要求。

### structured_complete

Arxiv 负责构造 Prompt：

```json
{
  "action": "structured_complete",
  "input": {
    "messages": [],
    "response_schema": {},
    "purpose": "arxiv_title_scoring"
  }
}
```

AI Provider 返回结构化结果。

## 两阶段评分仍属于 Arxiv

即：

```text
标题批量评分
↓
threshold 筛选
↓
摘要评分
↓
排序
↓
取 Top-N
```

这些全部继续留在 Arxiv Plugin。

不要把它们搬进 DeepSeek Plugin。

这样未来换 OpenAI / Claude / Ollama 时评分算法完全不变。

# 七、Arxiv 插件 Provider 绑定

新增通用 Provider Binding。

不要使用：

```text
Plugin A → Process.Start Plugin B
```

也不要让插件直接读取别人的 PluginData。

统一：

```text
Arxiv
   ↓
PluginHost Service Broker
   ↓
Provider
```

建议 Arxiv manifest 声明：

```json
{
  "uses": [
    {
      "service": "paper_snapshot_provider",
      "optional": true
    },
    {
      "service": "ai_provider",
      "optional": true
    },
    {
      "service": "translation_provider",
      "optional": true
    }
  ]
}
```

宿主保存绑定：

```json
{
  "io.github.kevendai.arxiv": {
    "paper_snapshot_provider":
      "io.github.kevendai.paper-snapshot-sync",

    "ai_provider":
      "io.github.kevendai.ai-deepseek",

    "translation_provider":
      "io.github.kevendai.translate-tencent"
  }
}
```

> 注：service 名带 `@1` 版本后缀，绑定表键也带（spec §3）；`binding_key` 才是无版本短名。

如果系统只有一个符合 Capability 的 Provider：

```text
自动作为候选
```

但仍应在 Arxiv 设置中明确展示：

```text
AI 服务：
DeepSeek AI
```

如果存在多个：

```text
DeepSeek AI
OpenAI AI

```

必须由用户明确选择。

禁止：

```text
按安装顺序选择
```

```text
priority 最大的偷偷成为 AI Provider
```

```text
失败后自动切换到另一个收费 Provider
```

例如：

```text
AI Provider
[ DeepSeek AI ▼ ]

翻译 Provider
[ Tencent Translate ▼ ]

论文同步 Provider
[ Paper Snapshot Sync ▼ ]
```

# 九、最终论文同步流程

这是整个改造最关键的行为规范。

## 用户手动同步

```text
用户点击“同步论文”
        ↓
Arxiv Plugin 启动
        ↓
计算当天 profile_hash
        ↓
检查本地有效缓存
        ↓
如没有可用缓存
        ↓
检查 Paper Snapshot Provider
```

### A. 存在 Paper Snapshot Provider

```text
get_snapshot
```

#### Snapshot 成功且匹配

```text
PaperBundle
↓
跳过 AI
↓
进入翻译阶段
```

不得因为装了 AI Provider 再评分一次。

#### Snapshot 不存在

进入 AI fallback 判断。

#### Snapshot 请求失败

例如：

```text
连接失败
超时
认证失败
服务器不可达
```

进入 AI fallback 判断。

同时记录：

```text
Snapshot Sync failed: ...
```

# 十、AI fallback 行为

这是强制行为。

只要当前同步没有得到有效 PaperBundle，并且存在 AI Provider：

```text
必须询问用户
```

不得自动调用。

提示建议：

```text
未能从论文同步服务获取今日推荐结果。

是否使用「DeepSeek AI」重新获取并评分今日 arXiv 论文？

此操作将调用外部 AI API，可能产生费用。

[使用 AI 评分]
[取消本次同步]
```

## 用户选择“使用 AI 评分”

流程：

```text
Arxiv 获取原始论文
↓
Arxiv 分类过滤
↓
调用 AI Provider
↓
标题评分
↓
摘要评分
↓
生成 PaperBundle
```

如果 Paper Snapshot Provider 可用：

```text
AI评分成功
↓
put_snapshot
```

上传失败不得导致 Todo 导入失败。

只记录：

```text
论文已生成，但上传 Snapshot 失败
```

之后继续导入。

## 用户选择“取消本次同步”

必须：

```text
立即结束同步
```

不得：

- 导入最新论文
- 导入未经评分论文
- 自动换另一个 AI
- 后台继续请求 API

结果：

```text
同步已取消：用户未启用 AI 评分
```

> 注（承载方式，spec §5.2）：上述询问**不是插件里的模态框**。插件返回 `attention` 后正常退出；TodoHost 在第二次 job 之前弹确认；用户确认才以 `allow_paid_ai=true` 重开 job。

# 十一、仅安装 Arxiv Plugin 的行为

Arxiv 必须可以独立安装。

但是“独立存在”不等于“自动导入未经评分论文”。

当：

```text
没有 Snapshot
没有 AI Provider
```

本次同步结束。

UI 提示：

```text
今天没有可用的论文推荐结果。

你可以：
• 安装论文同步插件，从远端获取已经生成的推荐结果；
• 安装 AI Provider，在需要时手动生成推荐结果。
```

提供按钮：

```text
[安装插件]
[关闭]
```

不能自行生成“最新 N 篇”。

# 十二、后台自动同步规则

Startup / scheduled sync 必须更加保守。

后台流程：

```text
Arxiv
↓
本地缓存
↓
Paper Snapshot
```

如果成功：

```text
正常导入
```

如果失败，但存在 AI Provider：

```text
绝对不能弹出阻塞窗口
绝对不能自动调用 AI
```

PluginJob 状态设为：

```text
attention
```

例如：

```text
论文推荐需要确认

远端论文同步失败。
可使用 DeepSeek AI 重新评分，可能产生 API 费用。

[使用 AI 评分]
```

用户主动点击后：

```text
attention
↓
manual resume
↓
AI评分
```

> 已确认：后台**不立即弹模态**，只置 `attention` + 磁贴提示，等用户主动点；否则会打断用户。

# 十三、标题翻译 UI

Arxiv 设置页中必须始终显示：

```text
□ 启用标题翻译
```

即使没有安装 Translation Provider。

## 没有 Translation Provider

控件：

```text
☐ 启用标题翻译
```

显示为灰色 Disabled。

旁边可显示：

```text
未安装翻译插件
```

点击灰色区域、说明文字或专门按钮时：

```text
尚未安装翻译 Provider。

标题翻译需要安装一个 translation_provider，
例如 Tencent Translate。

[打开插件市场]
[取消]
```

“打开插件市场”后：

```text
进入插件市场
↓
自动筛选 translation_provider
```

如果当前市场 UI 暂不支持 capability filter，则至少打开插件市场首页。

## 已安装 Translation Provider

启用复选框：

```text
☑ 启用标题翻译
```

下方：

```text
翻译 Provider：
[ Tencent Translate ▼ ]
```

如果只有一个，则默认选中。

如果多个，则用户选择。

## Provider 被卸载

保留：

```text
translate_enabled = true
```

但控件重新置灰。

显示：

```text
已启用标题翻译，但当前没有可用翻译插件
```

重新安装 Provider 后应自动恢复。

不要悄悄把 `translate_enabled` 改为 false。

# 十四、翻译执行时机

必须在：

```text
最终 PaperBundle 已确定
```

之后才翻译。

即：

```text
Snapshot / AI
↓
得到最终 Top-N
↓
Translation Provider
↓
TaskDraft
```

不要在 AI 评分前翻译所有候选论文，避免浪费翻译 API。

例如最终只导入 5 篇：

```text
只翻译 5 个 title
```

# 十五、翻译失败策略

Translation 是 enrichment，不是主同步依赖。

所以：

```text
Translation Provider 请求失败
```

不得使论文同步整体失败。

行为：

```text
记录 warning
↓
使用原始英文标题
↓
继续导入 Todo
```

UI 可以提示：

```text
论文同步完成，标题翻译失败，已使用英文标题。
```

# 十六、Todo 标题格式

PaperBundle 始终保留：

```text
title

```

TaskDraft 生成时：

如果：

```text
translate_enabled == true
```


否则：

```text
title
```

# 十七、SSDP 地址 Provider 关系调整

当前 SSDP Provider 对：

```text
arxiv.file_server
```

提供服务器 IP。

拆分以后，文件服务器不再属于 Arxiv。

应改成：

```text
paper_snapshot.file_server
```

新的关系：

```text
SSDP Server IP
      ↓
Paper Snapshot Sync
      ↓
Arxiv
```

而不是：

```text
SSDP
↓
Arxiv
```

Calendar 的：

```text
calendar.caldav
```

保持不变。

迁移期间可以暂时同时支持：

```text
arxiv.file_server
paper_snapshot.file_server
```

一个版本周期后删除旧 target。

# 二十七、最终目标状态

改造完成以后，Arxiv 不应该再是一个“大而全”的插件。

它应该只是：

```text
获取论文
↓
组织推荐流程
↓
获得 PaperBundle
↓
可选翻译
↓
生成 Todo
```

其他能力分别由 Provider 提供：

```text
AI 怎么调用？
→ AI Provider

标题怎么翻译？
→ Translation Provider

远端 JSON 在哪里？
→ Paper Snapshot Provider

服务器 IP 怎么发现？
→ Address Provider
```

最终依赖关系：

```text
                     Arxiv
                       │
       ┌───────────────┼────────────────┐
       │               │                │
       ▼               ▼                ▼
 Paper Snapshot        AI          Translation
       │
       ▼
 Address Provider
```

其中只有：

```text
Arxiv
```

是论文推荐业务的核心插件。

其余都是可替换能力。

最重要的用户行为约束：

```text
远端结果优先
→ 远端失败
→ 有 AI
→ 明确询问
→ 用户确认后才能产生 API 调用
→ 用户拒绝则立即结束本次同步
```

以及：

```text
标题翻译开关始终存在
→ 没有翻译插件时灰色
→ 点击提示安装
→ 有插件后才允许启用
→ 翻译失败不影响论文导入
```

实施过程中不得为了“方便”重新把 DeepSeek、腾讯翻译或文件服务器逻辑塞回 Arxiv Plugin。
