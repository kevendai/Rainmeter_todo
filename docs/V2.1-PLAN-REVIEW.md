# v2.1 计划评审（arXiv 解耦与 Provider 化）

评审日期：2026-09-16 ｜ 修订：2026-09-17（rev2，见 §八）｜ 评审基准：master（本体 2.0.4 已发布，arxiv 插件 1.0.2）

配套文档：`docs/V2.1-IMPLEMENTATION-PLAN.md`（需求原案）、`docs/V2.1-PROVIDER-INTERFACE.md`（冻结接口规格，实现以它为准）。

## 结论（先回答问题）

**需要更新本体，必须发 2.1.0。** 计划的 9 个 Phase 里有 6 个的核心工作量落在宿主：

| 计划要求的能力 | 现状 | 结论 |
| --- | --- | --- |

## 一、必须改本体的八项（逐条对到代码）

1. **manifest 增加 `provides` / `uses`** — 落点 `backend/PluginRuntime.cs` `PluginManifest`（第 43-73 行解析/校验）。**rev2 更正**：`capabilities` 白名单**不扩**（service 能力不进 `capabilities`），只把 `Capabilities.Count==0` 的硬校验放宽为"`capabilities` 非空 **或** `provides` 非空"（`PluginRuntime.cs:69`、`PluginPackageInstaller.cs:29,56-62`），并在 `schemas/plugin-manifest-v1.schema.json` 同步。
2. **Provider 绑定存储 + 解析** — 新文件 `%LOCALAPPDATA%\RainmeterDesktopWidgets\plugin-bindings.json` + 新解析器。必须宿主侧持有，否则"禁止按安装顺序/priority 偷偷选"这条规则无处落地。
3. **Broker 调用模式** — `PluginHostApp` 新增 `-Mode ServiceCall`：宿主自己按绑定解析 provider、校验、控超时、统一错误与审计。**好消息**：不算从零开始 —— 现在已经有一处"宿主代插件重跑另一个插件"的先例（`PluginHostApp.cs:38,61-64,72-73` 的地址插件刷新），把它泛化即可。
4. **Provider 注入** — `PluginRuntime.Invoke` 的 `context` 里补 `services`（每个 service 的解析结果）+ 新增环境变量 `RW_PLUGIN_ID` / `RW_PLUGIN_JOB_ID` / `RW_PLUGIN_HOST_EXE`（现在只注入 `RW_PLUGIN_DATA_DIR`、`RW_WINDOW_SCALE`，`PluginRuntime.cs:172-182`），让插件有稳定的 Broker 入口；**caller 身份只认这些变量，请求 JSON 里不许有 provider_id**。
5. **设置页动态 Provider 下拉** — `PluginManagerForms.ShowPluginConfig`（391-421）现按静态 `schema.properties` 渲染。新增 schema 标记（`x-provider: "<service>"`），由宿主在运行时填 `enum`（已装且 enabled → 名字；未装 → `未安装`），并支持 Disabled（现在**没有禁用控件先例**，只有 `x-address` 的 ReadOnly 先例可参考 :409）。
6. **"未安装 → 安装"路径** — 市场页要支持按 service 筛选 + 带参打开（`ShowSettings` 改签名 / 新增 `ShowMarket(service)`）。
7. **任务状态机加 `attention` + resume** — 写入侧（`PluginHostApp.cs:36,53,71,74,113,118` 附近）新增 `attention`；读侧对 `todo_source` **无效**（`PluginManagerForms.cs:373-388` 开头就 `if(!manifest.Capabilities.Contains("value_provider"))return "";`，且文案前缀是"失败："），**必须一并修**。resume = 用新 `input` 再跑一次该插件（`PluginAction <id> sync_with_ai <input.json> <output.json>`，`PluginHostApp.cs:30-31` 已支持传 input 文件），**不做进程挂起**；但 `TodoApp.cs:126-130` 的 `StartPluginCommand(action, id)` **不支持传 input**，需要加重载。
8. **迁移 `migration-v2.1.json`** — 落点 `PluginRuntime.MigrateInstallation`（234-245）旁。跨插件搬 secret 必须宿主做：插件互不读对方 PluginData，宿主已有替别人读写 secret 的先例（`TodoBackupService.cs:135-137,236,303`、`PluginManagerForms.cs:398,423-434`）。**rev2：复制不删除**。

## 二、计划里必须修正的六点

### 1. ⚠️ 让插件"弹窗询问是否付费评分"在本架构里是危险的，应改为纯非阻塞

计划 §10 要求手动同步时弹「是否使用 AI 评分」。但插件是**宿主 fork 出来的子进程**，宿主同步读它的 stdout 直到拿到 `result`。而现在 arxiv 里的"确认弹窗"是个**恒返回固定值的桩**（`ArxivPluginApp.cs:223-225`），说明这条路从来没真正通过。

> **rev2 措辞更正**：`宿主等 arxiv` + `arxiv 等用户` **不构成 2.0.2→2.0.3 那种"父等子、子等父"的环形互锁** —— 用户点了按钮 arxiv 还是会继续。原句说重了。
> **但结论不变**，理由换成更硬的五条：① 后台同步时没有前台窗口，模态可能没人看到却把 job 挂死；② 窗口焦点/置顶无法保证（Rainmeter 在桌面层、TodoHost 是隐藏窗口进程）；③ 超时语义混乱（等十分钟算不算超时？超时杀进程还是丢结果？）；④ Rainmeter 启动阶段（`Startup`）弹模态会拖住启动链；⑤ 无人值守下"等待"与"失败"无法区分。

**做法**：不是暂停原进程，而是让插件返回 `attention` 后**正常退出**，由用户点按钮重开一次 job（详见规格 §5）。

### 2. Broker 的传输方式必须定死（计划没写）

```
arxiv 侧：PluginHost.exe -Mode ServiceCall -RequestFile <请求文件>     （stdout/输出文件读回 JSON）
宿主侧：自己解析绑定 → 再 fork provider 子进程 → 返回结果
```
要点：**插件只报 `service` 名，绝不报 provider id** —— 绑定由宿主决定，插件无从"偷偷换 provider"。请求走**文件**而不是命令行/环境变量，避免中文 prompt 与超长 JSON 的转义坑。**rev2 追加**：caller 身份只来自宿主注入的环境变量；`Broker depth = 1` 写死；取消要传播到 provider。

### 3. capability 名字要带版本（**rev2 更正：只给 service 带版本，`api_version` 不动**）

建议 `provides: ["ai_provider@1"]` / `uses: [{service:"ai_provider@1", optional:true}]`。**`api_version` 保持 1**：它代表整个插件包/JSON Lines 基础协议，宿主现在写死 `ApiVersion != 1` 就拒（`PluginRuntime.cs:65`），而本次新增的 `provides`/`uses`/`context.services`/`ServiceCall`/`status` **全为加法式扩展**。Provider 协议单独版本化；宿主拒绝版本不匹配的组合，**不做降级匹配**。

### 4. `profile_hash` 的覆盖面要写进规范，并**同样适用于本地缓存**

- 补：`paper_bundle_schema_version`、`scoring_version`（评分算法版本）、prompt 的**规范化后文本**（CRLF→LF + Trim）。
- hash 输入表**定稿 11 项**，注意 **`abstract_threshold` 不存在**（schema 只有 `title_threshold`，`TodoPaperService.cs:75`），不得写进表。
- 本地缓存也必须带 hash 并在命中时校验；否则用户改了分类/阈值，当天缓存仍会被当"有效缓存"直接导入。
- 字段列表写死在文档里：将来加 profile 字段必须显式决定是否纳入，否则一次无意的加字段会让所有远端快照静默失效。

### 5. PaperBundle 是**不可信输入**（rev2 更正量程）

校验：体积上限、`schema_version` 必须 == 1（未知版本 → incompatible 不是 error）、`papers[].id` 去重、**分段量程**、`published_at` 可解析、`url/pdf_url` 必须 https + arxiv.org 域、`profile_hash` 不匹配 → `snapshot incompatible`（**不得导入**）。

**量程更正（重要）**：标题阶段 **0-10**（`DefaultTitlePrompt` "from 0 to 10"，`TodoPaperService.cs:26`；`ScoreStage(...,"title",...,0,10,...)`，`:727`；`Clamp(TitleThreshold,0,10)`，`:175`），摘要阶段 **0-50**（`:46`、`:733`）。所以 `scores.title` 必须 0-10、`scores.abstract` 必须 0-50。原案示例 `{"title":43,"abstract":46}` **本身就是量程混用** —— 43 作为 title 分在现有体系里不可能出现，照 0-50 放行恰好会漏掉这种 provider 错误。

### 6. 回滚必须真的可回滚（rev2 强化）

不只是"一键回退 1.0.2"的 UI：如果迁移把 arxiv 的 DeepSeek/腾讯/文件服务器凭据**搬走**，切回 1.0.2 会得到一个**没有配置**的插件。所以迁移必须**复制，不删除**，旧 config/secret 至少保留一个版本周期（spec §9.2）。

## 三、计划没提到但绕不开的六件事

1. **磁贴 UI 完全没提**。§10 §11 §12 里的 `[使用 AI 评分]` `[取消本次同步]` `[安装插件]` 都是**皮肤侧**的东西（Rainmeter INI/meter + Lua + `TodoRainmeterRenderer.cs`）。要单独立项（点击区域、状态文案、`attention` 怎么显示）。
2. **并发与取消**（**rev2 更正**）。原判"手动同步与 startup 同步可能重叠"**撤回**：两条路径都过 `InvokeLocked(..., exclusive:true)`（`PluginHostApp.cs:37`、`:72`、`:96-103`），互斥量 `Global\RainmeterPluginSync_<sanitized-id>`，不会并发，**不需要 `(source,date)` 单飞锁**。真正要解决的是取消：
   - `CancelPlugin`（`PluginHostApp.cs:115-119`）只杀**插件进程**，**不知道 Broker/Provider 子进程** ⇒ 取消 arxiv 后 DeepSeek 请求进程会变孤儿；
   - `WriteJob` 在 `state != "running"` 时把 `pid`/`entry` 删掉（`:107`）⇒ job 一旦收尾就再也取消不了；
   - 需要：job 记 `job_id` + `children[]`；按 provider → broker → consumer 顺序杀（沿用现有"进程身份已变化，拒绝终止"校验）；Broker/provider 监视父进程自退（沿用更新器 `WaitForProcess(parentPid)`）。
   - 连带 bug：重复点击时 `InvokeLocked` 抛"该插件已有同步任务正在运行"，冒泡后被写成 `failed`（`:75`/`:56`）⇒ **正在跑的任务被误标失败**；应保留 `running` + 提示文案，退出码 0。
3. **翻译要缓存**。只在最终 Top-N 翻译（计划 §14 ✅），但同一标题重算/重评会重复付费 → 按 `sha256(title)` 落翻译缓存。
4. **`x-advanced` 是死键**。schema 里用了 14 处，后端**完全没实现**，而 `docs/PLUGIN-API.md` 声称支持。本次新增 `x-section` 并真正实现渲染（分组 + 高级折叠），所有插件受益。
5. **权限无法强制**。`permissions` 只解析+展示，安装时还明说"不能限制系统访问"。所以 `billing: may_charge` 只能做**展示 + 宿主策略**（宿主在自动同步里一律不调用），**不要**写成"权限系统会拦截"。
6. **回滚会把 arxiv 卡死**。arxiv 2.0.0 的 `min_host_version` 必然是 2.1.0；用户回退本体到 2.0.4 时插件被 `PluginRuntime.cs:66` / `PluginPackageInstaller.cs:53-55` 拒跑，磁贴静默失去论文功能 ⇒ 必须有**可见提示 + 一键回退 1.0.2**。发布顺序：**先 SSDP 1.1.0（同时声明双 target）→ 本体 2.1.0 → 三个 provider → arxiv 2.0.0 最后**。

## 五、验收矩阵补充（计划 §25 之外）

11. Provider 返回**结构非法**的 bundle → 判 incompatible、记 warning、走 AI fallback 询问；**不导入、不静默吞掉**。
12. `schema_version: 2` 的 bundle → incompatible（不得当 error 重试）。
13. 绑定指向**已被卸载**的 provider → 等价于"没有该 provider"（不是失败），绝不能变成死循环或硬报错。
14. `profile_hash` 不匹配的**本地**缓存 → 视为无缓存（重走 snapshot / 询问 AI）。
15. 多个 provider 且用户未选 → 视为未绑定，询问流程里**不得**调用任何一个。
16. headless 下的 AI 询问 → 不允许自动同意：`provider_denied`、0 次 API、job 保持 attention。
17. **取消父 job** → arxiv / Broker / provider 三个进程都不残留。
18. **provider 试图二级转发** → `broker_depth_exceeded`（且 provider 环境块里没有 `RW_PLUGIN_HOST_EXE`）。
19. **`scores.title = 43`** → incompatible（量程混用）；**title 9 / abstract 46** → compatible。
20. **job running 期间重复点击同步** → job 保持 running，不得被写成 failed。
21. **回退本体到 2.0.4** → 拒跑但有可见提示；一键回退 1.0.2 后**配置仍可用**。

## 六、环境提醒（影响能不能验收）

**DeepSeek 成功路径需要真余额**：验收矩阵 #3「AI 评分成功」这条在余额不足时会直接撞 `HTTP 402 Insufficient Balance`（2.0.4 已把该错误做成可读中文并快速失败）。

- CI/沙箱**不要依赖 Ollama**（服务是否启动、模型是否下载、体积、CPU/GPU、生成非确定性都不适合 CI），改用 **`tests/FakeAiProvider`**（输入 prompt、返回固定分数）来打通 Broker、binding、confirmation、两阶段调用、PaperBundle、cancel 全链路。
- Ollama 可以做 2.1.x，但**不是 2.1.0 的 CI 前置**。
